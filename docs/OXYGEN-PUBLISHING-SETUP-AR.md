# أكسجين — نشر الواجهة وتشغيل المقالات

## ملفات الواجهة

الواجهة المعدّلة موجودة في:
`oxygen-ac-automation/assets/oxygen-maintenance-home.html`

الإضافة تحاول قراءة هذا الملف أولًا. عند عدم وجوده، تستخدم أجزاء الصفحة الاحتياطية `assets/page-part-*.txt`. لا تستبدل أجزاء الصفحة الاحتياطية بملف الواجهة؛ الملف الجديد هو واجهة كاملة مستقلة. تأكد من أن إصدار الإضافة الجديد تم رفعه قبل فحص الصفحة الحية.

## الدخول إلى لوحة التحكم

- لوحة ناشر ووردبريس: `/wp-admin/admin.php?page=oxygen-ac-automation`
- بوابة إدارة الواجهة: `/oxygen-admin/`

الدخول يعتمد على حساب WordPress وصلاحية المدير؛ لا توجد كلمة مرور داخل واجهة HTML.

## إعداد المقالات

من لوحة ناشر أكسجين يمكن ضبط كل نوع من العمل من 0 إلى 30 يوميًا:
- مقالات إرشادية جديدة.
- صفحات SEO خدمية.
- تحديثات لمقالات قديمة.

الإعدادات القصوى المقصودة 30 مقالًا إرشاديًا + 30 صفحة SEO فعلية من نوع WordPress Page + تحديث حتى 30 مقالًا قديمًا يوميًا. العدد الفعلي قد يكون أقل إذا لم توجد عناوين فريدة أو مقالات قديمة مؤهلة. هذا حجم نشر مرتفع؛ ابدأ بمراجعة المسودات، ثم زِد المعدل تدريجيًا بعد التحقق من جودة المحتوى وعدم تكراره.

**حماية النشر:** النشر التلقائي مفعّل افتراضيًا على التثبيت الجديد، لكن إعدادات التثبيت القائم لا تُستبدل تلقائيًا. النشر الفعلي يتطلب مفتاح OpenAI صالحًا ونجاح توليد نص عربي لا يقل عن نحو 200 كلمة؛ عند غياب المفتاح أو فشل التوليد يحفظ النظام المحتوى كمسودة بدل نشر قالب. راجع عينة من المحتوى قبل الاعتماد على النشر التلقائي، لأن 30 مقالًا + 30 صفحة SEO يوميًا حجم مرتفع ويجب زيادته تدريجيًا حسب الجودة. صفحات SEO تُنشأ كصفحات فعلية وليست مقالات. تحديث المقالات القديمة يحتاج مفتاح OpenAI ويضيف قسمًا تكميليًا مرتبطًا بمحتوى المقال؛ إذا فشل التوليد، يتجاوز المقال بدل إلحاق نص عام متكرر. تشغيل «شغّل الناشر الآن» يسمح بتجربة يدوية إضافية في نفس اليوم.

لتفعيل توليد OpenAI، أدخل مفتاح API من صفحة الناشر واحفظ الإعدادات. لا تضع المفتاح في ملفات المستودع أو الواجهة الأمامية.

## الجدولة

الإضافة تستخدم حدث WP-Cron باسم `oxygen_ac_daily_job`. تعيد الإضافة إنشاء الجدولة إذا لم يكن الحدث موجودًا، وتسجل آخر تشغيل لتجنب تكرار دفعة اليوم عبر Cron. أُضيف سير عمل GitHub Actions:
`.github/workflows/oxygen-wp-cron.yml`
يستدعي `wp-cron.php` كل 15 دقيقة. يفشل التحقق إذا أعاد الخادم صفحة HTML بدل استجابة صغيرة متوقعة، حتى لا يسجل نجاحًا زائفًا بسبب إعادة كتابة المسار أو التخزين المؤقت.

تحقق من تبويب **Actions** بعد أول تشغيل مجدول. إذا فشل، افحص سجل Hostinger وقواعد التخزين المؤقت والمسار `/wp-cron.php`.

## النشر إلى Hostinger

### نشر واجهة الموقع العامة
يوجد سير عمل `.github/workflows/deploy-oxygen-static-homepage.yml` لرفع `index.html` والواجهة الكاملة وأجزاء الاحتياط فقط إلى جذر الموقع العام. يحتاج نفس أسرار FTP بالإضافة إلى:
- `FTP_ROOT_DIR`: المسار الكامل لجذر الدومين في Hostinger، ويجب أن ينتهي بـ `/public_html/` (مثل مسار public_html الخاص بالدومين الرئيسي).

بعد ضبط الأسرار، شغّل **Actions → Deploy Oxygen public homepage → Run workflow**. ويمكن تشغيله تلقائيًا عند تعديل ملفات الواجهة في `main`.

### نشر إضافة WordPress
يوجد سير عمل منفصل:
`.github/workflows/deploy-oxygen-hostinger.yml`

أضف `FTP_SERVER_DIR` على أن ينتهي بـ `/wp-content/plugins/oxygen-ac-automation/`، ثم شغّل **Actions → Deploy Oxygen plugin to Hostinger → Run workflow**. هذا يرفع ملفات الإضافة فقط ولا ينشئ تثبيت WordPress أو يعدّل قاعدة البيانات.

**تنبيه مهم من الفحص الفعلي:** اختبار GitHub وصل إلى ملف الواجهة الحالي على الدومين الرئيسي برد HTTP 200، لكن `/wp-cron.php` يرجع HTTP 404 على كل من `oxygen11.com` و`googl.oxygen11.com`. هذا يعني أن نشر الواجهة العامة لا يثبت وجود WordPress في أي من هذين المسارين. يلزم تحديد جذر تثبيت WordPress الفعلي أو إكمال تثبيته قبل الاعتماد على توليد المقالات اليومي.

لا يحتوي المستودع على بيانات FTP، لذلك لا يمكننا رفع الملفات إلى Hostinger حتى تُضاف الأسرار المطلوبة.

## الفحوص

- `.github/workflows/php-lint.yml` يفحص صياغة ملفات PHP.
- سير عمل WP-Cron يسجل نتيجة التحقق من نقطة الجدولة.
- نشر GitHub للملفات لا يعني وحده أن الموقع الحي قد تم تحديثه؛ تحقق من نتيجة سير العمل وصفحة الموقع بعد النشر.
