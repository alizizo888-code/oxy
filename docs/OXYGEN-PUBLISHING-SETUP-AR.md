# أكسجين — نشر الواجهة وتشغيل المقالات

## ملفات الواجهة

الواجهة المعدّلة موجودة في:
`oxygen-ac-automation/assets/oxygen-maintenance-home.html`

الإضافة تحاول قراءة هذا الملف أولًا. عند عدم وجوده، تستخدم أجزاء الصفحة الاحتياطية `assets/page-part-*.txt`. لا تستبدل أجزاء الصفحة الاحتياطية بملف الواجهة؛ الملف الجديد هو واجهة كاملة مستقلة. تأكد من أن إصدار الإضافة الجديد تم رفعه قبل فحص الصفحة الحية.

## الدخول إلى لوحة التحكم

- لوحة ناشر ووردبريس: `/wp-admin/admin.php?page=oxygen-ac-automation`
- بوابة إدارة الواجهة: `/oxygen-admin/`

الدخول يعتمد على حساب WordPress وصلاحية المدير؛ لا توجد كلمة مرور داخل واجهة HTML.

## إعداد المقالات

من لوحة ناشر أكسجين يمكن ضبط كل نوع من العمل من 0 إلى 30 يوميًا:
- مقالات إرشادية جديدة.
- صفحات SEO خدمية.
- تحديثات لمقالات قديمة.

الإعدادات القصوى المقصودة 30 مقالًا إرشاديًا + 30 صفحة SEO فعلية من نوع WordPress Page + تحديث حتى 30 مقالًا قديمًا يوميًا. العدد الفعلي قد يكون أقل إذا لم توجد عناوين فريدة أو مقالات قديمة مؤهلة. هذا حجم نشر مرتفع؛ ابدأ بمراجعة المسودات، ثم زِد المعدل تدريجيًا بعد التحقق من جودة المحتوى وعدم تكراره.

**حماية النشر:** النشر التلقائي متوقف افتراضيًا على التثبيت الجديد؛ فعّله صراحةً من لوحة الناشر بعد إضافة مفتاح OpenAI والتحقق من عينة المحتوى. وحتى عند تفعيل النشر التلقائي، لا ينشر النظام محتوى المقال الجديد إلا إذا نجح توليد نص لا يقل عن 200 كلمة تقريبًا؛ إذا لم يوجد مفتاح صالح أو فشل التوليد، يحفظ المقال كمسودة. صفحات SEO تُنشأ كصفحات فعلية وليست مقالات. تحديث المقالات القديمة يحتاج مفتاح OpenAI ويضيف قسمًا تكميليًا مرتبطًا بمحتوى المقال؛ إذا فشل التوليد، يتجاوز المقال بدل إلحاق نص عام متكرر. تشغيل «شغّل الناشر الآن» يسمح بتجربة يدوية إضافية في نفس اليوم.

لتفعيل توليد OpenAI، أدخل مفتاح API من صفحة الناشر واحفظ الإعدادات. لا تضع المفتاح في ملفات المستودع أو الواجهة الأمامية.

## الجدولة

الإضافة تستخدم حدث WP-Cron باسم `oxygen_ac_daily_job`. تعيد الإضافة إنشاء الجدولة إذا لم يكن الحدث موجودًا، وتسجل آخر تشغيل لتجنب تكرار دفعة اليوم عبر Cron. أُضيف سير عمل GitHub Actions:
`.github/workflows/oxygen-wp-cron.yml`
يستدعي `wp-cron.php` كل 15 دقيقة. يفشل التحقق إذا أعاد الخادم صفحة HTML بدل استجابة صغيرة متوقعة، حتى لا يسجل نجاحًا زائفًا بسبب إعادة كتابة المسار أو التخزين المؤقت.

تحقق من تبويب **Actions** بعد أول تشغيل مجدول. إذا فشل، افحص سجل Hostinger وقواعد التخزين المؤقت والمسار `/wp-cron.php`.

## النشر إلى Hostinger

يوجد سير عمل يدوي:
`.github/workflows/deploy-oxygen-hostinger.yml`

لتمكينه من **Settings → Secrets and variables → Actions** في مستودع GitHub، أضف الأسرار التالية:
- `FTP_SERVER`: اسم خادم FTP من Hostinger.
- `FTP_USERNAME`: اسم مستخدم FTP.
- `FTP_PASSWORD`: كلمة مرور FTP.
- `FTP_SERVER_DIR`: مسار مجلد الإضافة في الاستضافة، ويجب أن ينتهي بـ `/wp-content/plugins/oxygen-ac-automation/`.

بعد ضبط الأسرار، افتح **Actions → Deploy Oxygen plugin to Hostinger → Run workflow**. هذا النشر اليدوي يرفع ملفات مجلد الإضافة فقط، ولا يعدّل قاعدة بيانات ووردبريس. لا يحتوي المستودع على بيانات FTP، لذلك لا يمكن تشغيل نشر Hostinger من GitHub قبل إعداد هذه الأسرار.

## الفحوص

- `.github/workflows/php-lint.yml` يفحص صياغة ملفات PHP.
- سير عمل WP-Cron يسجل نتيجة التحقق من نقطة الجدولة.
- نشر GitHub للملفات لا يعني وحده أن الموقع الحي قد تم تحديثه؛ تحقق من نتيجة سير العمل وصفحة الموقع بعد النشر.
